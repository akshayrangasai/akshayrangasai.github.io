There's a pattern I keep noticing in my workflow: the tools I reach for most are the ones I spent the least time configuring.

Not because they're the most powerful — usually the opposite. They're just simple enough that I never have to context-switch into "tooling mode" to get things done.

## The configuration trap

Every hour spent configuring a tool is an hour not spent on the actual work. That sounds obvious, but it's easy to forget when you're deep in a `.config.js` file telling yourself "this will save me time later."

Sometimes it will. Most of the time, you're optimizing for a future that never arrives.

## What "getting out of the way" means

A tool gets out of the way when:

- **Defaults are sensible.** You can start using it without reading the docs first.
- **Escape hatches exist.** When you do need to customize, the path is clear.
- **It doesn't demand attention.** No constant updates, breaking changes, or migration guides.

Static site generators are a good example. Markdown in, HTML out. Everything else is optional.

## The takeaway

Pick boring tools for boring problems. Save the interesting tools for interesting problems. And when in doubt, choose the thing that lets you start writing — or coding, or designing — in under five minutes.
